# BG-1547

**What was wrong:** A scenario record's `fallen` list was `["slime","",""]`, and the Weaver check-in's `happened` said "the player defeated someone" twice: two of the three slimes the player killed had no name.

**Root cause:** A group's followers are added to the cast with `name: ''` (`fillRosterAndGroups`, `src/scenario/validate.ts`), and `spawnNpc` (`src/library/spawn.ts`) set `names.current` with `opts.name ?? opts.label ?? t.label`, so an empty name was kept as the actor's name instead of falling back to the label, as it does when a cast entry leaves `name` out. Every reader of `names.current` then got `''`: the scenario record (`record` in `src/engine/scenarioEnd.ts`), the `happened` lines (`who` in `src/engine/happened.ts`, which turned `''` into "someone"), and what the player calls someone whose name they know (`callName`).

**What was done:** `spawnNpc` treats a blank name as no name, so a follower (or a cast entry the Weaver gave an empty name) is called by its label ("a slime"). The one place every NPC gets its name is fixed, so every reader above is covered. The NR27 group test in `tests/cases/s332-rosters.test.ts` now also checks that each follower's name is its label (it failed before the fix).
