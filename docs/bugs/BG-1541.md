# BG-1541

**What was wrong:** The creation screen named the Start's class perks as plain text ("Class perk at level 1: Any Road Will Do, As Far as the Road Goes."), so there was no way to read what a perk does before beginning. The same line also called the class's level 20 capstone, As Far as the Road Goes, a level 1 perk.

**Root cause:** `startFacts` in `src/ui/creation.ts` turned the class's perks into a flat list of names (`lib.perks[p]?.name`), dropping both the perk (so nothing could open its write-up) and the level that grants it (`levelPerks` flattened with `capstone` appended). The head line then printed that list as one string under a fixed "Class perk at level 1" label.

**What was done:** `startFacts` groups the class's perks by the level that grants them through the shared `classPerks` (its capstone at `classMaxLevel`). The line names each level ("Class perk at level 1: …. Capstone at level 20: ….") and each perk name is a text button that opens its story and Effect rows (`perkRuleRows`, now shared with the Perks board) in the movable panel, as other entries do (since BG-1571, a details pop-up, so it also works above full-screen pop-ups). The Start buttons' tips keep the plain names.
