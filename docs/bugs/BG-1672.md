# BG-1672

**What was wrong:** A target in the viewer's own title always showed in full to that viewer (PC3, `openingShown`),
whatever walls and openings stood between them inside a large title. A shooter and a target in one yard, with a garden
wall and its window between them, got no frame from the window: the target counted as fully shown.

**Root cause:** `openingShown` in `src/ruleset/objectCover.ts` returned 1 at once when `from.zone === zone.id`, before
looking at the sight line. That is a title deciding what is shown (AGENTS.md rule 8), a shortcut from the time a title
was taken to be one open room.

**Why it caused the symptom:** The walk along the sight line (`crossings`, `openingsOn`, `seesNow` from
`src/plan/line.ts`), which finds the last opening seen through and frames the target by it, never ran for two bodies in
one title, so walls and openings inside that title were never met.

**What was done:** The title check is gone; only a missing viewer returns 1. The same sight-line walk now runs for every
viewer, and a line that passes no opening still returns 1 as before, so two people in one open room are unchanged.

**Also affected:** `objectHidden` in the same file takes its furniture only from the target's title, so a piece on the
sight line in another title hides nothing: BG-1717. Searched `src/perception`, `src/views` and `src/ruleset` for other
same-title checks on what is shown: the rest pick a body's point only when it stands in that title (clutter, light),
which is not a shortcut on sight.

**Verified:** A temporary case test (a 40 m yard, a free-standing wall across it with a window, target 2 m behind the
window, viewer 13 m out on the far side, both in the yard) gave 1 before the fix and 0.55 after, the same as the PC3
hub example across two titles. `s384-windows` and `s383-object-cover` pass unchanged.
