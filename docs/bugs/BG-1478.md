# BG-1478

**What was wrong:** When a world was carried on to a new character, the foes who downed the last character looted the body (WP6 a). There the foe was a slime, and it took the coin, shield, bandages and the rest, leaving only an empty worn pack. Beasts and monsters that are not intelligent cannot loot.

**Root cause:** `stripBody` (`src/engine/loot.ts`), the one rule both looting paths use (`lootTheFallen` for WP6 a, `lootFoundBodies` for D-253 b), took every looter it was given. Neither caller asked whether the looter's race can loot at all. Each race already has an intelligence (intelligent, semi-intelligent or unintelligent, in `src/library/data.ts`), but looting never read it.

**What was done:** `stripBody` now lets only intelligent looters take. A semi-intelligent beast (a wolf, a dragon) or an unintelligent monster (a slime) leaves everything on the body, as the owner ruled on the decision card for this bug. The race's intelligence is read through a new shared `intelligenceOf` (`src/ruleset/body.ts`). Both spec homes say so (`scenarios.md`, `what-is-saved.md`). Covered by two new cases in `s272-carry-on-world` (a slime, and a wolf), which fail before the change. `s412-loot-found-bodies` still passes.
