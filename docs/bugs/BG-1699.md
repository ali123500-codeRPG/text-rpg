# BG-1699

**What was wrong:** `tests/unit/map-land-ui.test.ts` ("whole turn: … on the mill road your pin sits on its line") failed
in CI at `expect(road.line).toEqual(line.pts)` (32 points against 40) on some runs and passed on others, and always
passed alone.

**Root cause:** Two things together.
1. The dev page's land (`fakeLand`, `src/ui/fakeGame.ts`) keeps the region it draws in a module-level cache
   (`fakeRegion`) and never draws it again. `npm test` runs files in one shared module load per worker
   (`vitest.shared.config.ts`), so when `tests/unit/map.test.ts` ran first in the same worker it drew the region at the
   full CONFIG.REGION_SIZE_M (10 km), and this test, which sets 5 km before it starts a game, got that 10 km region.
   Which file a worker runs first changes from run to run, so the failure came and went. Reproduced with
   `vitest run --config vitest.shared.config.ts tests/unit/map.test.ts … tests/unit/map-land-ui.test.ts --maxWorkers=1
   --sequence.shuffle --sequence.seed=3`.
2. On the 10 km region the mill road's line starts inside Millbrook's square, so since BG-1679 the road's title starts
   where the line leaves the square: its line is the land road's line less that first stretch. The test still asserted
   the title's line was the whole land road line, the rule before BG-1679; the 5 km region happened not to show it.

**What was done:** `fakeLand` draws the region again when its size differs from CONFIG.REGION_SIZE_M. The test now
checks the BG-1679 rule: the title's line is the land road's line from where it leaves the settlement (every point
after its first is the land line's), its length is that line's, and your pin is your point along it. It passes on the
order above, and on the 10 km region alone.
