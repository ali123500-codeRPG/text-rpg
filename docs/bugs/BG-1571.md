# BG-1571

**What was wrong:** The class card on the Classes page (click a class in the class tree) named the class's level perks and capstone as plain text ("Level 1 perk: Any Road Will Do", "Capstone: As Far as the Road Goes at level 20"), so there was no way to read what a perk does. The same fault as BG-1541 on the creation screen.

**Root cause:** `openClassCard` in `src/ui/classTree.ts` turned the perk ids into one string of names (`perkNames`: `lib.perks[x]?.name` joined with commas), so nothing could open a perk's write-up. Reusing BG-1541's fix as it stood would not have been enough: it opened the details in the app's side panel (`openPanel`), which sits in the page layout under the full-screen Classes pop-up (`.fpop`, z-index 30), so the panel opened unseen behind it.

**What was done:** `perkButton` moved to `src/ui/perks.ts` and both screens use it. It opens the perk's story and Effect rows (`perkRuleRows`) in a details pop-up (`openPop`, violet edge for perks), which floats above the page and any full-screen pop-up. One details pop-up is open at a time (CP2), so a perk opened from the class card takes the card's place. The class card's perk names are these buttons, and the creation screen's (BG-1541) now open the same pop-up rather than the side panel. The inline look is the house text button with `perk-link`, so it keeps its look wherever it sits.
