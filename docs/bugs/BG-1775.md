# BG-1775

**What was wrong:** A Weaver check-in that answered "continue" with a change (a new question, scale or endings, SC12)
never changed the running scenario in play. The scenario kept its old question and endings, so a check-in could not
reshape it.

**Root cause:** In `src/scenario/apply.ts` (`applyStagePlan`), the branch that applies a check-in's change was an
`else if` chained after the branch that adds a plan's titles to the scenario's ground (`else if
(state.stage.scenario?.ground)`). Every scenario started from a plan keeps a ground, so for a check-in plan the ground
branch always ran first and the change branch never did. The SC12 test (`tests/cases/s188-checkin-changes.test.ts`)
built its scenario frame by hand without a ground, so the dropped branch was never exercised.

**What was done:** The check-in change is its own `if`, applied whether or not the scenario keeps a ground. The SC12
test's frame now has a ground, as in play; with the old chain it fails (the question stays `q`). Found while building
D-217 a (#1773), in the same lines.
