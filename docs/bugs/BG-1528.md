# BG-1528

**What was wrong:** Some moves left an actor with no point (Actor.pos) until the next turn's start, though position is spatial (GSM-50, metres, never "the title"). An event made by that actor then carried no point, was perceived as if it happened at the title's middle, and, when the player perceived it, `noteSightings` erased the journal's last spot (`lastSpot`) for that actor, so the player kept only the room (`lastKnown`). The scenario's opening events (the player's arrival, everyone's presence) and the follow event of an NPC coming through a frontier behind the player were built with no point at all, so the same held for them.

**Root cause:** Placement (placeAll, GSM-51) ran only at scenario setup and at each turn's start, and three moves cleared the point and left it to that next run instead of placing at once:
- `src/scenario/director.ts` `followAcross` (NW8): an NPC following the player through a frontier got `delete a.pos` ("placed at the next turn's start"). Reproduced: after `cross`, the guard stood in the grove with no point, and its follow event (`src/agents/director.ts`) had none.
- `src/engine/travel.ts` `travel` (TV6): the player's companions got `delete c.pos` at the trip's end ("placed beside the player next"). Reproduced: after a trip to Ashford gate the bandmate stood there with no point for the rest of the turn; any event it made then had none, and a perceived one erased its last spot.
- `src/engine/resolve.ts` (SD7): a window drop with no landing point (`opening.to`) cleared the point. Not reachable in play: `placeOpening` gives every window its landing point when its titles are drawn, and `fitBarrier` turns a doorway into a window before that.
Separately, the hand-built events in `src/scenario/apply.ts` (`stealthyArrival`, `openingEvents`) and the follow event never copied their maker's point, unlike `mk` in resolve.ts. And `noteSightings` (`src/perception/index.ts`) read a missing point as "forget the spot". `placeAll`'s own `delete a.pos` for a title with no outline cannot run in play: every drawn title has an outline, and the turn check's inside_zone rule reports any that has not.

**What was done:** Each move places at once with the existing rule: `followAcross` and the trip's end clear the old point and call `placeAll` right away (the same free spot the next turn's start would have given: the title's middle, or beside the player on a road), and the unplaced-drop branch does the same. The follow, arrival and presence events carry their maker's point. `noteSightings` only writes a last spot from an event's point and never erases one. The turn check's inside_zone rule now also reports anyone with no point in a drawn title, so a move that loses one shows at the turn's end. The GameEvent.pos comment and GSM-51 say everyone always has a point; the turn checker spec names the rule. Test s348's stand-in director now places the player as a stage plan does (it set the zone and no point).
