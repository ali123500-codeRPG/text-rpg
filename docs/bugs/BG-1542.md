# BG-1542

**What was wrong:** `npm run playtest` stopped on turn 1, right after the story started: `Cannot read properties of undefined (reading 'map')`. Nothing could be played or replayed.

**Root cause:** `scripts/playtest.ts` still read `links` from state zones (`st.zones[…].links`), in the turn loop's Map line and in `placeNextTo` (`--near-seller`, `--near-slimes`). Zones lost `links` when ways became openings on the floor plan (PZ10, `Zone` in `src/types/core.ts`); ways out are now read with `waysOut` (`src/plan/where.ts`), and the player view gives them as `zone.links`. The script was never updated because `tsconfig.json` type-checked only `src` and `tests`, and esbuild bundles without type checking, so the break went unseen. The same gap hid a third stale call: `personalityText` gained a `state` first argument, and the `--persona` line still passed two.

**What was done:** The Map line reads `buildPlayerView(st).zone.links`, as the play screen does (`src/ui/play.ts`); `placeNextTo` uses `waysOut`; the `personalityText` call passes the state. `scripts/playtest.ts` is now in `tsconfig.json`'s `include`, so `npm run typecheck` catches the next engine change it misses (node imports and `process` declared the way the other scripts do). Checked on the IAA-108 run's saved store: the old Map expression throws, the new one lists the green's three ways out.
