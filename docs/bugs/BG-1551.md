# BG-1551

**What was wrong:** After the player reported the slimes dead and was paid, the headman's stance toward the player went from neutral straight to friend, two steps, although QT13 gives a finished job one step friendlier.

**Root cause:** Two writers stepped the stance for the same deed, and the agent was never told about the code's step. In that turn the code handed the job in (`handInQuests`, `src/engine/resolve.ts:3373`, the headman saw it done), and `endQuest` (`src/engine/quests.ts:122`) stepped the giver friendlier, as QT13 says. Then `applyAgentEffects` (`src/engine/effects.ts:106-113`) applied the headman's Responder answer, which also held `stance: friendlier` for the same paid job. The stance rule all three NPC agents share (`STANCE_RULE` in `src/agents/prompts.ts`) never said which deeds the code already steps for, so the agent counted the job again. The same gap was there for every other code-made step: a job given up or failed (colder), a caught filch (`src/engine/filch.ts`, colder by `FILCH_CAUGHT_*_STEPS`), and a guard's suspicion raised or cleared (`src/engine/suspicion.ts`, GD2/GD4). The "unconvincing" impression in the same exchange is not part of this bug: by the Dialogue input rule (architecture-one-turn.md) the impression comes from the speaker's Persuasion tier, not from whether the words are true, and the headman trusted what he saw ("I saw it").

**What was done:** `STANCE_RULE`, shared by the Planner, Responder and Voice, now lists the deeds the code steps the stance for by itself and says to add no step for them. The information model's stance paragraph says the same. `stepStance` and the QT13, GD2/GD4 and filch steps are unchanged.
