### Turn checker

TQ1 (Ali, 13/11/2026): world rules checked after every turn, whatever feature ran (src/save/turnCheck.ts, one rule per line in RULES). In tests a broken rule fails the test (the w4-kit play() helper and every createGame turn); in a playtest it stops the run and writes turn-check.log; in the game it is filed as bug code turn\_check and play goes on. Rules: real\_zone, inside\_zone, move\_event (a zone change has a move, a ride on the player's travel, or a logged caught\_up), dead\_still, event\_refs, fight\_ends, invariants (the load checks: one player, one current class, slots, grips, worn covers, stacks), one\_item\_one\_place, condition\_range, links\_real, view\_pronouns, heard\_only. A rule an open bug breaks in named tests is listed under that BG in tests/harness/turnCheckSetup.ts until its fix lands. A new feature adds its own rule.

Soak run (TQ2 b): a seeded random player plays whole turns through createGame with no Claude calls (its Parser answers are random intents from its own PlayerView; every other call fails, so NPCs run on code routines and fallbacks), with the turn checker every turn (tests/soak). When the player falls the world starts again (the rng goes on) until the turn budget is spent, every 10 turns the game reopens from its save, the random player tries every Parser action and gear op, and the same world and seed must play the same turns. A throw the game catches so play can go on (a background Planner, the story text save) is filed as code\_error and fails a strict test. Every CI run plays a small one (with the director, so new ground is fallback ground) on the test village; a large one runs nightly with new seeds (.github/workflows/nightly.yml). A failure names its world and seed, so it replays.

Replay set (TQ3 a): retired (Ali, 20/11/2026, TE1 a). Its recordings stopped loading when old saves ended (#819), so it replayed nothing; the saved soak worlds went with it (TE2 a).

Parser test set (TQ4, nightly only): about 40 player lines, many from past Parser bugs, parsed by today's Parser prompt on the real model against the test village (tests/parser-eval, PARSER_EVAL=1, through the signed-in `claude` CLI that playtests use, scripts/claude-cli.ts). It runs as a daily scheduled Claude task, not in GitHub CI, so it needs no API key there; a line that misses twice in a row fails and becomes a BG-n bug. A new Parser bug adds its line.

PR rule (TQ5 a), for every feature and fix PR: (1) a new action, actor kind, view field or shared rule adds its rows to the completeness tables, which fail CI when a row is missing (tests/unit/action-table.test.ts: every Parser and NPC action decides its reach need and who can take it); (2) a change of meaning (zone links to metres, numbers to keys) is searched for across the whole repo (code, tests, docs) and every old use changes in the same PR, with the search named under "Siblings checked"; it adds no guard test (Ali, 20/11/2026); (3) a test is added only when a break would go unnoticed and no existing test or smoke flow covers it (the PR names the covering test or the search), in the cheapest form that catches it: a unit test for a pure function, a whole-turn test through createGame (tests/harness/turn.ts wholeTurn: the Narrator narrates every event, other agents fail unless queued so NPCs use their code minds) only when the turn itself is the risk, never setting by hand what the turn itself sets, or a browser smoke test for what the page shows; never a match on source text; a duplicate or a test that guards nothing may be removed, naming what covers it (Ali, 20/11/2026, testing review); (4) the PR description fills "Siblings checked" and "Tests" (.github/pull_request_template.md; the PR rule workflow fails without them).

Browser smoke tests (TQ7): five flows on the play page built as in production, on the real game with an in-memory save and a stand-in Claude (tests/smoke, `npm run smoke`, its own CI job with Chromium): load and create a character, play a turn, report a bug, switch to the agent's story and back, restore a backup from the GM view. The stand-in Parser reads every line as a look or, after "say ", as words; the Narrator narrates every event; other agents fail, so NPCs use their code minds. Time is virtual, so the turn windows pass at once.
