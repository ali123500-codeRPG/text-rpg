- OQ-9: The database holds at most 25,000 documents, shared by the library and every story. The caps on documents per collection, total size and write rate are not published. The build must measure them in a throwaway artifact (a full database refuses new documents) before N, the backup counts and the proposal caps are set. Ali, Questions hub page "Open questions (OQ)", 21/11/2026, OQ-9 a: measure it now, in a throwaway page of its own, never the game's database. Measured 21/11/2026 with the Database Limits Probe artifact (runtime contract 0.2.98), recorded under Persistence, "Platform limits": total size about 100 MB (95 MiB of document bodies), no separate cap per collection, no write-rate limit met up to 45 writes a second. Size runs out first: with the save benchmark (`scripts/save-baseline.ts`), backups are about two thirds of a story's size, so BACKUPS\_KEPT matters most. Still open: whether TURN\_RECORDS\_KEPT, BACKUP\_EVERY and BACKUPS\_KEPT keep their values against these caps (asked on a decision card, #1696).
- OQ-11: Prompt caching in the Claude-call capability (sample). Settled by the runtime 0.2.96 type definitions: the capability takes no system prompt (input is a prompt string or user/assistant turns under fixed platform framing; standing instructions go in a leading user turn), has no cache\_control or other prompt-caching option, and reports no token usage. Its only documented cache is answer replay: a call with the same input (every turn), modelTier, model, effort, images and verb replays the stored answer without contacting Claude, for 5 minutes by default or up to 24 hours with cache.gcTime. Replay never helps a call whose input changes. Whether the platform caches a long shared prefix on its own was not in the docs, so it was measured with the Prefix Cache Probe artifact (same prefix vs. prefix changed at the first line vs. short prompt, timed to first text, quick tier, both input forms; Ali, Questions hub page "Open questions (OQ)", 21/11/2026, OQ-11 a: build the probe as a throwaway page; the owner opens it once). Result (one run of the probe, 21/11/2026: quick tier, a 120,000-character start, 5 timed calls per case, median time to first text): as one text, same start 1,116 ms, first line changed 1,689 ms, short prompt 758 ms; as two turns, 1,151 ms, 1,427 ms and 705 ms. Repeating the start saved 62% (one text) and 38% (two turns) of the extra time a changed start took, so the platform does reuse a repeated long start, at least in part, in both input forms. Latency estimates may count on a repeated fixed part answering sooner; cost estimates still assume no saving, because the capability reports no token usage. Catalogs (templates, body types, routine sets, items) change only with libraryVersion, so they sit right after the fixed instructions as a stable prefix and gain from this reuse; a library edit refreshes the prefix.
