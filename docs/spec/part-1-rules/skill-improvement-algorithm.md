### 6. Skill improvement algorithm

Runs entirely in code at the end of each scenario, for the rolls the scenario pays (Scenario-end growth, below). Claude has no part in it. How a single roll gains is being redesigned (EG16, the skill-gain roll document); this section describes the code as it is.

```
Rolls are made in rounds. At the start of each round:
  Total  = sum of raw x share (D-374): share = 100%
           - 95% for its own tag - 5% per tagged skill sharing
           a group with it, itself included
           + 5% per flawed skill sharing a group with it,
           itself included (D-377)
           (a lone tag counts 0)
  Burden = max(0, floor((Total - Potential) / K))
  Burden holds for the round; the next round works it out again,
  so the first round's gains weigh on the second.

In each round, every skill with rolls left makes one (SG1 C):
  Cap    = SKILL_CAP (100); Tagged: + TAG_CAP_BONUS (20) = 120;
           Flawed: - FLAW_CAP_PENALTY (25) = 75
  Tagged : Margin = d100 + (Cap - Skill + Bonus) - GROWTH_ROLL_NEEDED (100)
  Normal : Margin = d100 + (Cap - Skill - Burden + Bonus) - 100
  Flawed : Margin = d100 + (Cap - Skill - Burden + Bonus) - 100
  Bonus  = TAG_GROUP_ROLL_SHARE (0.05) x true skill of each OTHER
           tagged skill sharing a group (D-374 TB5)
  Gain   = Margin / GROWTH_MARGIN_PER_POINT (15), rounded up;
           Margin 0 or below gains nothing (D-383)
  No hard limit (D-374 TB7): at Cap a natural 100 is Margin 0, so raw
  stops exactly there (further only with a group bonus).
  (All-XXX checks run at scenario end, not here: LF3)

Repeat rounds until no skill has rolls left. Clear all marks.
```

- **Marks** (Ali, 07/11/2026, "Skill progression: options" SP1–SP11): a use marks the skill actually rolled (SP4) and, when a stand-in made the roll, also the skill the action asked for (Ali, 09/11/2026: both learn, each against its own window, so a skill far below its stand-in can still rise), success or failure, when the opposition is from MARK\_WINDOW (10, placeholder) below the skill's raw value up to MARK\_WINDOW above its true value (SP2; Ali, 09/11/2026, replacing ±10 of raw or true), so true-skill perks widen what teaches you. A skill not on the sheet learns from use too (Ali, 09/11/2026): it counts as raw 0 and joins the sheet with its first gain. Close calls teach too (Ali, 09/11/2026, an "or" with the window): a contest or defended attack whose final tier gap is exactly 0 marks both sides' skills whatever their values. Wins against stronger sides teach too (Ali, 13/11/2026): a contest or defended attack the player wins has no top to its window, so only the floor (MARK\_WINDOW below raw) applies; a loss still needs the full window, and so does the skill a stand-in rolled for. Passed checks teach the same way (Ali, PG2 a, 14/11/2026): a passed check has no top to its window, however hard its number; a failed one still needs the full window. A search for hidden items, gear or secrets passes when it finds every one it rolled against; a stash beats no one, so it keeps the window. The opposition is a check's target, or the other side's true skill in a contest, attack or defense; notice rolls follow the same rule (SP6). Endurance is marked by any hit that costs health when the attacker's true skill is inside Endurance's learning window, the same test armor skills use (replacing SP5's single hit of 10% health or more), so a foe far weaker than your Endurance stops teaching it. One mark per skill. Only the player keeps marks; NPC progression comes later (SP7).
- **Stacking marks** (Ali, 11/11/2026, SM1): a skill's marks are counted per engagement (or per scenario, outside one). The first mark owes an improvement roll, and so does every MARK\_STACK\_EVERY-th mark after it (config, 1: every mark owes a roll; Ali, 14/11/2026, D-318, was 2 and before that 3). Counts clear when the engagement ends or the scenario breaks (SM3).
- **Scenario-end growth** (Ali, 12/11/2026, growth proposal EG7, EG8, EG10, EG13, EG17 and the rounds rule; replaces instant skill-ups, SM2, and the per-engagement roll, SP3). While a scenario runs, marks only count: each owed roll waits (Progression.marks). When the scenario ends, it pays rolls = round(owed rolls × tier share × ending factor), plus GROWTH\_ROLLS\_PAST\_CRIT (1) per step past Critical Success on its event roll, plus GROWTH\_LOW\_LEVEL\_BONUS (1) while the character level is below GROWTH\_LOW\_LEVEL\_BELOW (5) (src/engine/growth.ts scenarioRolls, payScenario). A scenario that marked nothing pays nothing. Tier share (GROWTH\_TIER\_SHARE, by the scenario's event-roll tier): Critical Failure 0.5, Failure 0.6, Near Miss 0.7, Success 0.8, Great Success 0.9, Critical Success 1. Ending factor (ENDING\_FACTOR, judged endings by which ending it was, EG5 b): resolved 1; lost and broken off 0.75; left, escaped, interrupted and worn out 0.5; every factor is kept between ENDING\_FACTOR\_MIN (0.5) and ENDING\_FACTOR\_MAX (1.25), so no ending the Weaver writes or picks pays outside them (EG17 a). There is no scale factor (EG13 a): every mark is worth the same in a moment, a situation or an episode. The rolls are dealt to the marked skills by their owed rolls (largest remainder; EG6 a) and made in rounds (section 6). Marks, achievements, levels and All-XXX steps earned in free roam wait for the next scenario's end (BG-217). An inner scenario pays only for its own marks; the bigger scenario's waiting rolls and achievements are kept apart (ScenarioFrame.held) and come back when it resumes, or join the inner's when both end. Level-ups wait for the same moment (EG8): spendXp does nothing while a scenario runs, and the ending takes every level the XP allows. Gains show in the scenario-end gains summary (LogLine.scenarioGains); failed rolls show nothing and nothing goes to Claude (SP11). CONFIG.GROWTH\_AT\_SCENARIO\_END false brings back rolls at the end of the turn of the mark. Scaling: the payout counts rolls, not points, so it works the same at 50, 75, 100, 150 and 200; what a roll does at each skill is the improvement roll's (section 6), which stops at the mortal limit (LF4).
- **Essences** (Ali, 12/11/2026, growth proposal section 2: EG1 a, EG2, EG3 b, EG4 a, EG9 a, EG11 b, EG12 a, EG15 b; src/engine/essence.ts). An essence is a package of true skill (and later a trait, D-229) the player may take into a limited number of slots. It is a small foreign addition that sits on the Thread, never a strand of it (NM2), and it is not body: its points are true skill, count toward perk milestones and All-XXX (EG4 a), and ignore the mortal limit. **Rows:** the library `essences` table (ES ids, src/library/essenceIds.ts): a name, where it comes from (a race, a body type, or deed), a weight, the skills its points go to with weights, an optional trait and quirk (perk rows), and a story. Today's rows (Gel Patience from slimes: Slam 2 + Scent 1; from the humanoid body type, so humans and elves alike (NE2 a): Gate-Warden's Habit: Block 2 + Earshot 1, Street Instinct: Dodge 2 + Insight 1, Haggler's Ear: Barter 2 + Earshot 1, Tavern Brawler: Strike 2 + Persuasion 1, and Lookout's Eyes: Eyesight 2 + Earshot 1 (NE3 a), the Watchers' and Hunters' only row; every person fits it, so it is picked at weight 0.25 against the others' 1 (Ali, decision card 16/11/2026): a guard gives it 1 time in 5. Every row's pick weight lives in one table, CONFIG.ESSENCE\_PICK\_WEIGHT (Ali, 16/11/2026: weights for all essences, as a table, for balance); naming no race or body type, so the fit rule hands each beast the rows of its natural weapons (NE1 a): Fang and Nose: Bite 2 + Scent 1, Horn and Hide: Hooves and Horns 2 + Hide 1, Claw and Pounce: Claws 2 + Dodge 1, Lashing Tail: Tail 2 + Hide 1; Hard-Won Habit from deeds) are placeholders; the content round is D-229, and a row for one race can still be added there. **Template lists** (Ali, 13/11/2026, Template Essences EN1–EN7): every NPC template carries its own essence list, worked out in code (`templateEssences`, src/engine/essence.ts) from its race and the sheet its copies spawn with (`templateSkills`). A row is on the list when its race or body type matches, or it names neither (EN2 a), and the template's weighted average in the row's skills (raw × tier) is at least ESSENCE\_FIT\_SHARE (0.4, placeholder) of its best skill (EN1 a). Because the fit is a share, a template keeps its list at every scale. A template may carry several rows and rows may be shared. Deed rows never go on a list. NpcTemplate.essences is a hand-set list that replaces the worked-out one (EN3 b); an echo (unique template) carries only its own essence, a row with from.echo, which is never worked out onto any other list, and a test checks every echo has exactly one. Today: slime Gel Patience, guard Gate-Warden's Habit, barkeep Haggler's Ear, thief Street Instinct, patron Tavern Brawler. **Every NPC has one** (Ali, 16/11/2026, questions hub page "Every NPC has an essence", NE1-NE5): every template and every person or beast mix the composer accepts carries at least one row (test s341), including Untrained beasts: a beast whose Resolve is above every weapon skill (an Untrained one: Resolve 50, weapons about 15) fits no weapon row, so it carries Cornered Nerve (Resolve 2 + Scent 1; EssenceDef.from role and over: only the Beast role, only when Resolve is above every skill in its role's high band), which the slime template also carries (Resolve 50 over Slam 30) (Ali, 16/11/2026, closing D-362). **Owner bounds** (Ali, 17/11/2026, provision only, no row sets one yet): a row may set `from.min` and `from.max`, skill id to bound, and is on an NPC's list only when each named skill of the owner (raw × tier) is at least / at most the bound; a bound is a number or a step of the ladder past 100 (beyond 150, mythic 200, transcendent 300, divine 400, read from that one ladder), so a row can be kept to Divine owners or kept from them. No top: Divine+ (500) and up meet a Divine minimum. The library viewer shows them as "Owner needs". An NPC the player kills or bests whose list is empty is flagged as a bug report, essence\_gap (NE4; no fallback row). Non-combat NPCs hand theirs over the existing ways: a death, being bested in a Great Success ending, or Extract Essence (NE5 a; D-250 stays parked). **Sources:** a foe the player hurt (Mind.hitByPlayer) rolls once, ever, on the turn it lies dead (Mind.essenceRolled): an essence comes only from a death, never from a defeat (Ali, BF24, BG-199), on its template's list, or with no template the same rule on its own sheet (EN4; EG9 a: the source fixes the kind). A scenario that ends resolved at Great Success or better makes one appearance roll at its ending moment (TF20 b, EB1, Ali 14/11/2026): with anyone **bested** in it (ScenarioFrame.bested, dead or not), it offers **two** essences and the player takes one (EssenceOffer.pair: taking, giving or selling one lets the other go; passing one keeps the other): one from anyone bested, at random, and one from one of the ESSENCE\_TOP\_BESTED (3, placeholder) bested with the highest power; each comes from that person's list, is measured from their skill (raw × tier, EB1 b) and has its own quality roll. With nobody bested, a deed row whose points go to the skill marked most, measured from the player's true skill. **Bested** (BS1-BS3, Ali 14/11/2026; bested() in src/engine/xp.ts): defeated by the player (payDefeats), or a foe on the other side that stood down from the player's own offer to stop (persuasion, lie or bribe; offer.ts standDown), once per person, ever (Mind.bested). It is not a defeat and pays no XP; it feeds the ending's list and the Bested chain (AC237-AC241: 1, 10, 100, 250, 1000 at reward levels −2, −1, 0, I, II; −2 is a new bottom level and pays 0 XP by the one curve). Also bested (BS1 d): a guard's suspicion talked away (suspicion.ts clear, "talked"); a won persuasion, lie or threat against someone hostile or opposed to the player before the words (speech.ts resolveSpeech, BESTING\_SPEECH); and a filch from someone hostile or opposed that the Filching contest leaves uncaught (resolve.ts doFilch). Staying unseen never bests. BS4: a bested and a defeated person weigh the same in the ending draw. **Two rolls** (Ali, 13/11/2026): first the **appearance roll**: an essence appears when d100 ≤ ESSENCE\_APPEAR\_CHANCE for the source (a notable foe 100, any other foe 5, an ending at Great Success 60, at Critical Success 70; placeholders). D-274 (Ali, 13/11/2026, FS18): every beaten foe rolls once, ever; a notable foe's essence always appears, so its quality roll alone decides whether it fades. A foe is **notable** when it is a unique (an echo too), its template or its race is tagged notable (NF5 a: a creature that matters by what it is; no race carries the tag yet), or it filled a roster hook tagged notable: the Leader, the Rival, a Seat of the Great or a Warden (NF4 b; HookKindDef.notable, marked on the actor as Core.notable when it is cast), or it is the head of a larger group (NF7 a: a Bandit company's captain or a Watch garrison's watch captain; GroupPart.notable, marked the same way; a small group's leader is not) (notable(), src/engine/essence.ts). Power never makes a foe notable (Ali, 21/11/2026, Questions hub page "Notable foes: fewer early essences", NF1: "we need to fundamentally change what a notable foe is away from their power"), and neither does being rolled (NF2 a). Scenario key players are parked (IEI-1737). Group leaders count only on a higher rung of groups than today's (NF3 a, NF7 a: "actual leaders only, not a group of 3 bandits"), which the grouping review builds. A held essence's trait or quirk is a perk its holder owns (source essence) once, however many held essences carry it, and it goes with the last of them (FP8); their points still add. Then the appeared essence makes its **quality roll**: margin = d100 + base − ESSENCE\_ROLL\_NEEDED (100, the growth proposal's formula; the generous roll Ali picked) on the normal tier table, natural edges included; base ESSENCE\_ROLL\_BASE: a foe 80 (holds 81%: 25% common, 50% fine, 1% rare, 5% epic), an ending at Great Success 80, at Critical Success 100 (95%). Together with the appearance roll, an essence is offered 81% of the time from a notable foe, about 49% from a Great Success ending and about 67% from a Critical Success one. Threadbound item actives (Call the Toss, All or Nothing) work on the quality roll only. Near Miss or worse on the quality roll: the essence fades (logged essence\_faded; the Narrator tells it as a strand that slipped away, NarrationView.essencesFaded); Success common, Great Success fine, Critical Success rare, each step past it one grade higher (a natural high on a Critical Success is one such step; the code had stopped at rare until CS13) (ESSENCE\_GRADES: common, fine, rare, epic, legendary; past the last, ×ESSENCE\_GRADE\_PAST\_MULT each). **Points** = max(1, round(ESSENCE\_SHARE (0.07) × source skill × grade multiplier (ESSENCE\_GRADE\_MULT 1, 1.5, 2.5, 4, 6))), split over the row's skills by weight (largest remainder). The source skill is the foe's raw × tier in those skills (weighted), or for an ending the player's own true skill. **Room** (EG2): ESSENCE\_SLOTS\_BASE (1) + one per ESSENCE\_SLOT\_EVERY (7) character levels: 2 at 7, 3 at 14, 4 at 21, no top. **Choosing:** an offer waits ESSENCE\_OFFER\_TURNS (10) turns, or until a new scenario starts; /essence lists offers and held essences; /essence take N fills an empty slot; with every slot full, /essence take N give M gives up a held one first; /essence pass N lets it go for good. **Removal** (EG3 b, EG15 b): only at rest (out of any fight, no hostile in the zone); the essence is lost, and it costs ESSENCE\_REMOVE\_LEVELS (1) × the current level's XP, except the first ESSENCE\_FREE\_CHANGES (3) changes, a removal or a swap, which are free (EB3, Ali 14/11/2026; Progression.essenceChanges); the XP bar may go into debt, which new XP pays off first. **Shown:** when an offer is waiting that the player hasn't seen yet, a pop-up opens on Play once the turn lands (src/ui/essences.ts maybeOfferPop, once per offer): the essence's name, grade, story, its points as chips ("+1 Dodge", "+1 Insight"), slots used and how long it waits, with Take it (with every slot full, one "Take it, give up X" button per held essence), Let it go and Decide later; the buttons run the same /essence commands. The Character page has an Essences tile (slots used, and a violet "◆ N on offer" while one waits) that opens the Essences pop-up (CP4): slots as tiles, held essences with their chips, empty slots dashed, and On offer with the same buttons, the two offers of a pair side by side under "Take one: the other goes". The play sheet has an Essences row naming the held ones and a violet "◆ N on offer" link that opens that pop-up. The character card itself has no Essences lines, so essences show once on the Character page, in that pop-up; the ending line's gains summary lists essences offered (ScenarioGains.essences); the Narrator gets essences offered this turn as name and story only (NarrationView.essences, rule 22; the thread may be named, EG11 b, never numbers). **Achievements** (EG12 a): First Knot (I, take your first essence) and Room for No More (II, every slot full at character level 8 or higher). Scaling: points follow the source's skill, so at a source of 50 / 75 / 100 / 150 / 200 a common essence gives 4 / 5 / 7 / 11 / 14 points and a rare one 9 / 13 / 18 / 26 / 35; the grade table and the slots have no top. Past 100 essences and perks are how skills keep rising. **Essences open their skills** (Ali, 13/11/2026): a held essence that adds true skill to a skill opens that skill whatever its tree's or its own access rules (skillBlock), and taking it puts any missing skill on the sheet at raw 0 so its points count. Letting the essence go closes the skill again; the raw-0 entry stays and counts 0. A body that lacks the part a skill's role needs is D-255.
- **Essence extraction** (Ali, 14/11/2026, DX1-DX5 on the Essences page; src/engine/extract.ts, action extract). A blessing of Imbra, minor goddess of essence manipulation (D-311: gods and blessings; the blessed Start grants it), the perk Extract Essence (NM2: it works on the essence, a small foreign addition to someone's Thread; no god touches the Thread itself), lets the player, as their main action and within grip reach, take the essence of someone who is Down (Incapacitated) or has surrendered, so a surrendered foe still standing qualifies (DX2 c; a willing target is D-312). No roll decides it (DX3 a), and it uses up the target's one essence roll (Mind.essenceRolled), so a later death gives none. The essence comes from the target's own list, always appears and never fades: its quality roll (base ESSENCE\_ROLL\_BASE.foe) sets the grade, and below Success gives Common (DX4 b). Its points are worked out from the target's skills first (raw × tier); then the target is left **Hollowed** (a quirk, perk source inflicted; Core.hollowed): each of the essence's skills keeps 1 − HOLLOWED\_SHARE\_MULT (2) × the essence's share (7% × the grade multiplier) of its true skill, and every skill keeps 1 − HOLLOWED\_ALL\_LOSS (10%), multiplied, for good (DX5 a; hollowedMult in src/ruleset/perks.ts). It counts as an attack on the target (DX6 a; setAttackOverrides): the target, though beaten, and its bandmates who see it fully turn hostile to the extractor. No fear is paid: bandmates already paid "A bandmate goes down" when it fell, as with any blow on someone Down. The offer is an EssenceOffer with source extract. Only the player extracts, since only the player takes essence offers. (Down or surrendered, replacing Down and broken or surrendered: owner, 21/11/2026, #1462.)
- **Passing on essences** (Ali AT75, 13/11/2026: ES1 a, ES2 a, ES3 a, ES4 a, ES5 a, ES6 a + permanent, ES7 a; src/engine/essence.ts). Only an offer the player hasn't taken can be passed on (ES1); it stays an essence and goes straight to someone (ES2; an essence carried as an item is parked as D-249). **Give:** /essence give N to a name in view; the receiver must be within grip reach and have room, and takes it in with no yes needed (ES4, a gift). **Room** (ES3): an actor with a progression record (the player, unique NPCs today; permanent vs unique is D-148), into slots by the player's rule (ESSENCE\_SLOTS\_BASE + one per ESSENCE\_SLOT\_EVERY levels); its points are their true skill (essenceSkill). **Sell:** /essence sell N to a name; the buyer must hear the order (as an item sale), not be wary, and pay the buying price for its value (trade.ts buyingPrice, one equation with items: SELL\_SHARE, haggling and Hard Bargain). **Value** (ES5): points × ITEM\_VALUE.skillPoint × ESSENCE\_VALUE\_MULT (10, placeholder): a common essence from a source of 50 / 75 / 100 / 150 / 200 is 40 / 50 / 70 / 110 / 140 coin, a rare one 90 / 130 / 180 / 260 / 350, no cap. **Buyers** (ES6): a seller (Trader class) takes it into a free slot if it has a record, else holds it (Actor.essenceStock) to sell on; a unique NPC who is no seller buys only into a free slot (Ali: "I should also be able to sell to permanent"). A sale can be refused (wary, no coin, no room); a gift only by having no room. The receiver remembers it (a memory line). NPCs selling or giving essences to the player are parked as D-250 (ES7).
- **Training actions** happen only under a tutor; designed later (SP1, SP8). Beyond the mortal limit stays later (SP9).
- **StartingTotal:** the Total (raw at its D-374 share) at creation. A record only; it never changes.
- **Potential:** the Total at which Burden begins. Can be changed later by perks or events. At creation it is the fixed POTENTIAL (300, placeholder) for every character. Any character, NPC or player, may carry its own value instead, set case by case: an NPC template's potential, or a value set on one player character.
- **K:** *placeholder*, default 20.
- **Shown** (Burden review, Ali 14/11/2026, BU3 b): Burden shows only once it is above 0, and only in a skill's pop-up on the Character page (an untagged skill: "Burden −N to improve" and the untagged total against Potential).
