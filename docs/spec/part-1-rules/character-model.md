### 3. Character model

Skills are grouped into trees of exactly three. Example only: Tactics = Preparation, Cleverness, Logistics.

**Combat skill trees** (minimum for the first build; skill names are *placeholders*):

- Combat – Arms: light weapons, medium weapons, heavy weapons
- Combat – Ranged: light ranged, medium ranged, heavy ranged
- Combat – Unarmed: strike, grapple, improvisation; they behave the same for now (Part 5 §5). Improvisation is fighting with whatever is at hand: improvised weapons (Part 5 §7) roll it (Ali, 07/11/2026). Every improvised base has two modes (Ali, 09/11/2026): a melee **strike** and a ranged **throw** (the Throw action, like throwing a vase: reach 0 + the throw's +2, combined roll of Improvisation and the ranged skill of its class), the strike rolled with Improvisation. Unarmed skills stand in for both; Arms skills also stand in for the strike and Ranged skills for the throw (`AttackMode.standInFns`, at the usual stand-in share). Natural weapons is a creature-only skill outside every player tree (creatures' natural attacks roll it)
- Combat – Defense: dodge, block, parry
- Fortitude (Ali, 10/11/2026, MB5, MB31, MB32): endurance, resolve; the third slot is open. Resolve has the Morale function (Will group, XP factor Full); it sets max morale and rolls the morale roll (Part 3, Morale).
- Armor – Conventional (Ali, 08/11/2026, AR1–AR3): light_armor, medium_armor, heavy_armor; function armor in the Defense group; blocked for amorphous bodies. What the skill does while worn (AR4) and how it improves (AR5) are parked (D-184); equip requirements will read it (EQ1–EQ7, levels pending).

Endurance sets total HP (Part 3, Total HP). An average fighter has 50 in a combat skill; this is the design reference point. All-XXX perks apply to these trees as to any other.

**Other skill trees** (placeholders; each is its own tree):

- Perception: sight, hearing and insight (insight answers lies, Part 3). Sight and hearing are tagged with the Sense role.
- Stealth (Ali, 08/11/2026, ST1–ST19): sneaking, combat\_stealth and vanishing. Sneaking and Combat Stealth have the same use, split by engagement: Combat Stealth inside an active engagement or for an attack (an ambush included, BG-343), Sneaking outside one. Vanishing breaks the sight of someone who already sees you, in or out of an engagement, and counts as a combat skill for the rating. Each stands in for the others at 0.5×. For the character rating, Sneaking counts as a notice skill and Combat Stealth as a combat skill. Renaming, moving or adding skills stays a data edit (a tree lists its skills; a skill's tree is read from that list).
- Speech: persuasion, intimidation, barter. No body-part role.

The trees' skills are designed with character and mob generation. A perception roll uses sight for an event perceived by sight and hearing for one perceived only by sound (the cue from computePerception); when both apply, the higher. Combined checks (sight with hearing) are to be explored later.

**First-build skill list.** The first build has these skills, by id: melee\_light, melee\_medium, melee\_heavy; ranged\_light, ranged\_medium, ranged\_heavy; unarmed\_strike, unarmed\_grapple, unarmed\_natural; dodge, block, endurance; sight, hearing; persuasion, intimidation, barter; plus the class trees (Swordsman: riposte; Sword-dancer: blade\_dance; Slime: tremor) and insight; sneaking and combat\_stealth are in. Which trees an actor can use comes from each tree's access rule (Part 4 §4, Skill tree access); the creation screen offers the trees a new swordsman can use. Natural attacks and fallback.attackSkill name one of these ids.

**Skill substitution.** Any roll or check may use another skill that shares a function with the named skill (Skill functions, below) at reduced efficiency: that skill's effective skill × SUBSTITUTE\_EFFICIENCY (0.3, Ali 08/11/2026, F4; perks can raise or lower it). Code computes every candidate and uses only the highest value after efficiency. Example: intimidating with intimidation 20 and persuasion 100 uses persuasion at 30. The named skill counts at full value, and the roll is recorded against the skill actually used.

**Typed IDs** (ID review, Ali, 09/11/2026). Every library ID is a type prefix plus a number, never a name: skills SK, functions FN, groups GR, classes CL, achievements AC, services SV, perks PK (`src/library/perkIds.ts`), items IT (`src/library/itemIds.ts`), skill trees TR (`treeIds.ts`), races RC and body types BT (`raceIds.ts`), NPC templates TP (`templateIds.ts`), and the small tables in `tableIds.ts`: body-part roles RL, healing sources HL, clock rows DU, zone kinds ZK and attack modes AM; each counted from 1 within its type. Agents see perks as `{ id, name }`; a perk move the Parser names instead of giving its id is read as its id. A minted or improvised item's story ID is built from its base item's ID (`IT2_m12_1`, `IT21_i7`); the Parser still names an improvised weapon's base by word (improvised_light, improvised_medium, improvised_heavy), and code maps the word to its item (`IMPROVISED_ITEM`). Body types now carry a display name; the Weaver sees body types as `{ id, name }`. Roles and attack modes carry display names (the `attackModes` table; a natural attack may keep its own name, such as fists). Agents see a weapon's modes as `{ id, name }`, and a mode an agent names instead of giving its id is read as its id (`modeIdOf`); natural attacks are `natural:<AM id>`. The Weaver writes a zone's kind as its ZK id from `catalogs.zoneKinds`. The prefix shows what kind of thing an ID is, so IDs of different types never collide. Ordered scales, tags and categories, body parts, NPC behaviour (activities, routines, routine sets), place kinds and story-world IDs keep their word keys: ordered scales use stable keys plus one names table, tags and categories are fixed string enums, and body parts and NPC behaviour are words the Weaver and Planner write. **Skill IDs** (Ali, 09/11/2026). Every skill's ID is fixed (`src/library/skillIds.ts`, `SK`), never its name, so renaming a skill touches only the names table (`skillNames.ts`). Data and saves store the ID; code refers to skills through `SK` (e.g. `SK.eyesight` = SK14). IDs are never reused or renumbered. A standing defense (dodge/block), a sense function (sight/hearing), an armor weight and a weapon class map to their skill through `DEFENSE_SKILL`, `SENSE_SKILL`, `ARMOR_SKILL` and `CLASS_SKILL`; no skill ID is built from text. Functions and groups have fixed IDs too (`src/library/functionIds.ts`: `FN` FN1–FN19, `GR` GR1–GR13), so a function and a group with the same display name (Defense, Ranged, Stealth, Influence) never share an ID; names live in FUNCTION_NAMES and GROUP_NAMES (functionNames.ts). Agents see each skill as `{ id, name }`, and a skill an agent writes by name or old alias is read as its ID (`skillIdOf`). **Perk names** (BG-319, 19/11/2026): code never types a perk's name; every label, deck entry and roll-breakdown source reads it from the library with `perkName(id)` (`src/library/index.ts`), so renaming a perk touches only its library row. A guard test (s303) fails on a perk name typed in code outside the library.

**Skill functions and groups** (Ali, 08/11/2026, F1–F8). Each skill's library entry lists its narrow functions, and a skill may have several; stand-ins read functions. Each function sits in one broad group; a 40 perk's +1 and defeat XP read the group. Current list: docs/skill-tags.md. Exception pairs (`CONFIG.NO_STAND_IN`) never stand in for each other even when they share a function: dodge and block (Ali, 09/11/2026). **Sense rolls are function rolls** (Ali, 09/11/2026): a sight roll (stealth contest, ambush notice, Look) rolls the sight function, so every skill with that function counts at full value and the higher effective skill applies (tier multiplier still applies): Eyesight for sight, Earshot for hearing (`RollRequest.fn`). **Tremor** (Ali, 13/11/2026) is no sense function: it augments Earshot, adding its true skill × tier to every hearing roll, and never reaches sight. A function roll marks only the skill that rolled. Its situational modifiers (light, Night Eyes) follow the skill that rolls, not the function (Q3, Ali 09/11/2026): a hearing roll ignores light.

- Melee group: arms (melee\_light, melee\_medium, melee\_heavy), unarmed (unarmed\_strike, unarmed\_grapple, unarmed\_improvised, unarmed\_natural)
- Ranged group: ranged (ranged\_light, ranged\_medium, ranged\_heavy)
- Defense group: defense (dodge, block)
- Health group: health (endurance)
- Will group: morale (resolve)
- Notice group: sight (sight), hearing (hearing); tremor sits in the group and augments hearing
- Stealth group: stealth (sneaking, combat\_stealth, vanishing)
- Influence group: influence (persuasion, intimidation, barter)
- No function: riposte and blade\_dance. Each joins the Melee and Defense groups directly and augments one skill with its full value on every roll: riposte augments parry, blade\_dance augments dodge (PR #270)

**Skill states** (one per skill):

| State | Counts toward Burden | Affected by Burden | Improvement roll |
| --- | --- | --- | --- |
| Tagged | No alone; below 0 beside other tags in its group (D-374); +5% per flaw in its group (D-377) | No | 1d100, cap 120 |
| Normal | Yes, less 5% per tag and plus 5% per flaw in its group (D-374, D-377) | Yes | 1d100, cap 100 |
| Flawed | Yes, less 5% per tag and plus 5% per flaw in its group, itself included (D-374, D-377) | Yes | 1d100, cap 75 |

**Tags in the Total** (D-374, TB1 a on the Questions hub page "Tags and Burden", Ali 17/11/2026): each skill's raw counts toward the Total at a share: 100%, less TAG\_BURDEN\_SELF\_PCT (95%, placeholder) for its own tag, less TAG\_BURDEN\_GROUP\_PCT (5%, placeholder) per tagged skill sharing a group with it, itself included. A lone tag counts 0% (as before); an untagged skill beside one tag in its group counts 95%; two tags in one group count −5% each, so their raw lowers the Total and the whole Burden. Burden stays one number, and tagged skills ignore it. **Tagged group-mates help the roll** (TB4 b, TB5 c): every skill adds TAG\_GROUP\_ROLL\_SHARE (0.05, placeholder) × the true skill of each other tagged skill sharing a group with it to the room in its improvement roll, tagged or not; a skill never helps itself (D-376: true skill or raw at the balance check).

**Flaws in the Total** (D-377, FC4 a on the Questions hub page "Flaws at character creation", Ali 18/11/2026): the mirror of the tag's group share. Each flawed skill adds FLAW\_BURDEN\_GROUP\_PCT (5%, placeholder) to the share of every skill sharing a group with it, itself included; a tag and a flaw in one group cancel. A flawed skill alone counts 105%; three flaws in one group make each of its skills count 115% (burdenShare in src/ruleset/burdenTotal.ts). Scaling: Burden counts raw, which stops at 75 for a flawed skill and 100 for an untagged one (D-383), so the extra Total stops growing there (at most about +5 per group-mate per flaw); past 100 true skill grows from perks, essences and gear, which Burden never touches.

A Flaw is something the character functionally struggles to improve; every character chooses exactly CREATION\_FLAWS (3) at creation, one per tag (FC1): its cap is 25 lower (FLAW\_CAP\_PENALTY), so it trains to 75 and slows well before it. Tags and flaws move only the cap; every state rolls one d100 (no roll advantage or disadvantage). A skill that becomes Flawed above 75 keeps its raw and gains nothing more by training.

**Limits:**

- 100 is the mortal limit (SKILL\_CAP), the cap in an untagged skill's improvement roll; a tagged skill's cap is 120 (TAG\_CAP\_BONUS 20, EG16; 25 until D-374 TB7). The cap is not a hard limit (D-374 TB7): raw trains until the roll runs out, exactly at the cap (D-383), so a tagged skill can pass the mortal limit by training alone. **The improvement roll** (Skill Gain Roll Options, SG1 C, Ali 12/11/2026) is one d100: margin = d100 + (cap − raw − Burden) − GROWTH\_ROLL\_NEEDED (100, placeholder; 90 until D-374 TB7), and the gain is the margin ÷ GROWTH\_MARGIN\_PER\_POINT (15, placeholder), rounded up; margin 0 or below gains nothing (D-383; the tier table's +2 / +3 / +4 until then). The room left below the cap is the bonus, so the roll gets harder smoothly with no wall; at raw = cap a natural 100 is margin 0 and gains nothing, so raw stops exactly at the cap, unless a group bonus (D-374 TB5) adds room. A flawed skill's cap is 75 (FLAW\_CAP\_PENALTY 25, Ali 12/11/2026); tags and flaws move only the cap, and every state rolls one d100. A tagged skill has no Burden, and each skill's own cap is in the roll too (GROWTH\_CAP\_IN\_ROLL, SG3 a), so a tagged skill at 100 rolls like an untagged 80 and a flawed skill at 50 like an untagged 75. Natural edges do not move the roll (SG2 a; LF4: no natural roll forces a gain). Odds of any gain with no Burden (D-383): 75% at raw 25, 50% at 50, 25% at 75, 1% at 99; average gain about 2.25, 1.1, 0.35 and 0.01 a roll. Scaling: raw ends exactly at its cap (100, tagged 120, flawed 75), further with a group bonus (+5 at a group-mate's true skill 100, +10 at 200); perks, achievements and gear still carry true and effective skill to 150, 200 and beyond. Workaround mechanics for raw come later (D-6).
- **No cap past training** (D-3, settled by CS21): the training cap above is the only cap, and it limits raw skill alone. True skill and effective skill both go past it with no top: perks, achievements, essences, gear and augments carry a skill past 100, and the true skill past the cap is what the 120 and 140 milestones read. Conditions (wounds, fatigue, morale) are roll modifiers, not a step of effective skill.

**Three skill values** (Ali, 07/11/2026):

- **Raw skill:** what training gave. Burden, Total and skill improvement use raw skill only.
- **True skill:** raw skill + perks that raise that one skill by a flat amount and are always on (e.g. a ladder's Training milestone, +5). Ladder milestones and all-XXX perks read true skill. It has no cap of its own, so a ladder's boosts can carry a skill past the mortal limit of 100 toward the 120 and 140 milestones.
- **Effective skill** (computed for every check and roll, in order): true skill → + gear → × the skill's tier multiplier → + combined-check perks → + situational skill perks. No cap applies (D-3); conditions are modifiers on the roll.
- **Skill tiers** (Ali, 08/11/2026). Each skill has a tier on the SKILL\_TIERS scale (tier\_0, tier\_1, tier\_2), set in the library. The tier gives the skill's final efficiency multiplier (CONFIG.SKILL\_TIER\_MULT): tier 2 is 1×, tier 0 is 0.5×, and tier 1 is 0.75× (a placeholder). Every skill is tier 2 except the Slime senses skill (tremor), which is tier 0. The rating reads the skill at its tier (X18–X23).

Derived, never saved; the Character page shows true skill, with raw skill beside it when they differ.

Gear is a flat bonus to effective skill unless an item says otherwise. Standard kit (an average fighter's minimum equipment) gives one +25 per roll, shared by all kit pieces: pieces never stack (*placeholder*).

Wounds are no longer part of effective skill: the health-track level and body-part role penalties are a roll modifier type (§4, Combat rolls). They apply to rolls only (settles OQ-15, Ali, 07/11/2026); no no-dice checks are left (OD11 a), so they reach every skill use.

**Character fields:** defined in Part 4 §4 (a Core every actor has, plus Progression, Mind and Journal modules). Part 4 adds race, body type and classes.
