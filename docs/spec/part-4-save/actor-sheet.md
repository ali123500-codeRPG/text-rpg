### 4. Actor sheet

The player and every NPC share one sheet shape: a Core every actor has, plus optional modules. Roll code reads Core only, which guarantees one resolution path for everyone.

| Module | Who has it | Holds |
| --- | --- | --- |
| Core | Every actor | Race, body type, skills and states, classes, stored perks, condition, inventory, standing defense, public label |
| Progression | Player; NPCs only if NPCs improve (deferred) | StartingTotal, Potential, XP, unspent perk points, marks |
| Mind | NPCs | Control, morale, beliefs, overrides, knows facts, current routine and its anchor, routines list, slot bindings, alarm state. The agenda flag is derived, not stored; the band moved to the Actor |
| Journal | Player | Secrets learned, facts witnessed, last-seen state slots, names known |

Promoting an NPC to recurring adds a module; it never converts the sheet. A companion needs no module: it is any member of the player's band.

**Race and body type** (BR1–BR9, Ali 08/11/2026). The body type is the shape; the race is what the being is. Every race names exactly one body type (BR5), its HP multiplier (BR2), optional natural armor (BR6), its own natural attacks and fallback attack skill on top of the shape's (BR3), and innate perks and quirks. An NPC template and the player's build name a race, and the body type comes from it. Races today: Human and Elf (humanoid, ×1), Slime (amorphous, ×0.6), Dragon (winged quadruped, ×3). Defeat achievements count both the body type and the race (BR8). Tree access rules may name either (BR9); a tree the shape already blocks is not blocked again on the race.

**Skills.** General skills are open to every actor unless a perk or race excludes them. Each class adds its own tree of three skills. Exclusions are derived from the library and never stored.

**Skill tree access** (Ali, 08/11/2026, "Skill tree access" TA1–TA11). Every tree has its own access rule in the library (TreeDef.access), and each tree is coded on its own. A rule has up to three lists of conditions: **Must** (every one holds), **Either of** (at least one holds, when listed) and **Blocked by** (any one closes the tree). A block always beats an opening (TA2). A tree with no rule is open to everyone. A condition names one source: a race, a body type, a class with a minimum class level (default 1; the class counts while Current or Previous, never Unlocked, TA3), or a perk (quirks included); a new kind of source is one more case in one check. A skill in a tree the actor can't use counts as 0 (rolls, HP, the rating) and can't be raised; its points are kept and come back with access (TA4 a). Rules are per tree (TA8), with one exception: a skill can carry its own rule on top of its tree's (SkillDef.access, SR1 below). Rules hold for the player and every NPC: a test fails if a template gives a skill its actor can't use (TA9). Trees a character can't use are hidden on the creation screen and the character sheet unless the character has points in them; those show "Blocked by: …" or "Needs: …" (TA10). Today's rules: Swordsman must have class Swordsman; Tremor senses needs race Python or Giant spider (AB11, AB19); Perception is open to everyone, but its skills carry their own rules: the skill Scent needs an animal race or Slime (AB18), and Eyesight, Earshot and Insight are blocked by body type amorphous (TA6); Natural weapons and each of its skills need a body or race with an attack rolling that skill (AB16, worked out from the attacks); Hide needs a race with natural armor (AB20); body type amorphous blocks Melee, Ranged, Unarmed, Speech and Tools (no hands or voice, TA6). A block the shape gives is not repeated on the race (BR9). **Speaking races** (Ali, 08/11/2026, SR1): each race is tagged if it can speak (RaceDef.tags 'speaks': Human and Elf yes, Slime and Dragon no), and a condition can name a race tag. Intimidation is open to anyone with the Speech tree; persuasion and barter must have a speaking race. Banked: TA7 (Tools, lockpicking) and TA11 (nested groups of conditions), D-113.

**Classes.** Each class an actor knows is saved with its state and its class level:

| State | Meaning |
| --- | --- |
| Unlocked | Offered at level-up. Same as not having it: tree unusable, class level 0 |
| Current | Exactly one. Receives every new level for persistent characters |
| Previous | A former current class. Keeps its levels; its skills stay usable |

Putting a level into an unlocked class makes it current, and the old current class becomes previous. Class perks come at class levels set in the library (normally 10 and 20) and are derived. Previous-class skills keep improving like any other skill. Returning to a previous class is deferred.

**Player creation.** The player builds the sheet by point-buy on the creation screen (https://claude.ai/artifact/HW45ivigqwZ5VDo4PWPv9u): 100 points over the open skills (CREATION\_POINTS, every Start; Ali 14/11/2026), an untagged skill at most 30 (CREATION\_MAX\_UNTAGGED) and a tagged one at most 40 (CREATION\_MAX\_TAGGED) at creation (creationCap; untagging a skill above 30 lowers it to 30), the class floors as minimums, exactly 3 Tagged skills and exactly 3 Flawed skills (CREATION\_FLAWS, FC1 on the Questions hub page "Flaws at character creation", Ali 18/11/2026: one flaw per tag). A flawed skill is any open skill that is not tagged and takes at most 20 points at creation (CREATION\_MAX\_FLAWED, FC3); a skill is never both. Each creation row has two icon toggles after the skill name, tag and flaw (dim until set, then lit gold or red, aria-pressed; SD9); the Character page shows a flawed skill's red − (FLAW\_MARK), whose pop-up says it learns slower and stops at 75 (FC5). Flaws, like tags, stay for the whole story (FC6, D-379). Flaws earn nothing at creation; choosing quirks for benefits is D-378 (FC2). The recommended build flaws Persuasion, Barter and Sneaking \[Proposed\]; a race that can't learn one flaws its lowest open skills instead. The screen opens on a recommended build and shows HP, attack, standing defense and the odds against one slime as points move. The story starts only when every point is spent, 3 skills are tagged and 3 are flawed. StartingTotal is the sum of the untagged skills at that moment. The player starts with the starter kit their skills meet (below) and 20 coin (placeholder), at their Start's level (1 for every Start today; START\_LEVEL 4 is only the default for a Start that names none). **Starts** (Ali, 09/11/2026; renamed from starting classes, DX1, 14/11/2026). A Start is one way to begin on the creation screen, a library table of its own (`starts`, IDs ST… in src/library/startIds.ts, StartDef), apart from classes, so a start need not have a specific class and character creation can grow. A start names its class (StartDef.classId), or takes it from what it gives (the blessed start: its god's class); its creation points and level (StartDef.points and level, defaults CREATION\_POINTS and START\_LEVEL; the level is the class's), the age picker's default (StartDef.age) and its story line. The screen lists the starts in table order, each with its class tier, points and level; a blessing's tier never shows on the creation screen (the blessed start reads "a random god's blessing" and its Blessed class's tier, Seasoned). **A Start with no class** (CC6 b, Ali 14/11/2026): a start with neither a class nor a blessing begins with no class, at level 0 whatever its row says (startLevel), with the default class (Commoner, ClassDef.fallback) open to pick (unlocked, level 0); XP banks, so levels wait until the player picks a class, and picking one takes every banked level at once (src/library/spawn.ts classlessStart, defaultClass). No start is classless, and none is planned (CC9: no). The Swordsman start (ST1) was removed (Ali, 14/11/2026; ST1 is retired); the Swordsman class stays and unlocks in play. Unwritten Legend (ST2, the late bloomer; the first Start, and the default): the unique class Unwritten Legend, level 1, no floors, and its level 1 perk Any Road Will Do (every function's stand-in share +0.2; UL1). The A Nobody start (ST3) was removed (CC3, Ali 14/11/2026; ST3 is retired); the A Nobody class stays, opened at Commoner's top level. The Threadbound (ST4; TB7, Ali 12/11/2026): the class Threadbounded (tier 4, Heroic: TB11), level 1, no floors, and its level 1 perk What Was Always Yours, which gives a random Threadbound item of Rank IV or higher (Part 5 §9). **The Blessed** (ST5; DX1, Ali 14/11/2026): level 1 (CC3 a), named The Blessed (CC4 a); it begins with a random god's Tier V blessing: a god is picked at random among those who give a Tier V blessing, then one of that god's Tier V blessings, seeded by the story id (src/ruleset/blessings.ts rollBlessing), given with source 'start'. The god is rolled, and shown, when the story starts (CC5 a). It begins in that god's Blessed class (ClassDef.blessedBy), level 1. While no god gives a Tier V blessing the start can't begin (validateBuild, and the screen greys it out). **Blessed classes** (DX1): a variant per god, "Blessed by X", tier 2 (Seasoned); one opens (unlocked, level 0) for any character that god blesses. Today only Blessed by Imbra (CL10); its class perk and capstone, about earning a higher blessing from the god, are to come. A character's stranger label is its start class's ClassDef.label. **Class-level perks:** ClassDef.levelPerks lists perk ids by class level; a character gets them (source 'class') when the class reaches that level, at creation or on a level up. **Class IDs** (Ali, 09/11/2026): every class has a fixed ID (`CL` in src/library/classIds.ts: Swordsman CL1, Unwritten Legend CL2, Sword-dancer CL3, Commoner CL4, A Nobody CL5, Trader CL6, Threadbounded CL9, Blessed by Imbra CL10, A Somebody CL13); code and saves use the ID, so a class can be renamed in the library alone. **Class tiers** (Ali, 09/11/2026): every class has a tier on the ordered scale CLASS\_TIERS (lowest to highest: Common, Trained, Seasoned, Renowned, Heroic, Legendary; ClassDef.tier stores the key tier\_0 to tier\_5), shown on the creation screen and the class tree, to compare classes and to place NPC templates later. Commoner Common, Trader Common, Blessed by Imbra Seasoned, Swordsman Seasoned, Sword-dancer Seasoned (mirrors the Swordsman), Merchant Trained, Guard Trained, A Nobody Seasoned, A Somebody Renowned, Threadbounded Heroic, Unwritten Legend Legendary. **Class unlocks:** ClassDef.unlock lists true skill per skill; a player without the class unlocks it (state unlocked, level 0) when every one is met, checked after improvement rolls. Swordsman (tier 2, Seasoned) unlocks at Parry 80 and Medium or Heavy Weapons 60, and its level 1 perk Blade Against Blade (PK155) opens the Swordsman tree (Riposte). ClassDef.unlockAny is a list of either-of groups: in each group at least one skill must also be met. **Unlocks are floors** (Ali, 10/11/2026): a class's skill floors are its own floors plus its unlock conditions (`classFloors`), so every character of a class meets what unlocks it. An either-of group is met when one skill in it reaches its value. A template with a class has its minimums raised to them (`templateMinimums`; an unmet group raises the skill the template has most of), and the village guard template carries the Guard class. ClassDef.unlockPerkWith needs an active perk whose numbers reach the listed ones (PerkDef.hearingReach: zone links added to hearing; Keen Ear 1, and hearing reach sums it over perks). **Merchant** (Ali, 10/11/2026): a tier 1 class (top level 10) unlocked by Trader (tier 0) at its top level, 5 (ClassDef.unlockClass, a number or 'max' for that class's top level), or by Barter 75 on its own (orUnlocks). Trader's capstone Known at Every Stall (PK99) no longer unlocks it and has no effect yet: a new Trader capstone comes later (D-358). Its tree (Merchant, TR15) holds one skill, Shrewd Dealing (SK33), Merchant's advanced barter. **Guard** (Ali, 10/11/2026): a tier 1 class (CL8) that unlocks with any weapon skill at 40 (Light, Medium or Heavy Weapons, or Light, Medium or Heavy Ranged), any armor skill at 40, Block or Dodge at 30, and a perk that sharpens hearing (`hearingDb`: Keen Ear, which patrolling templates have). No tree or floors yet. **Skills augmenting skills** (Ali, 10/11/2026; a frequent theme to come): a skill can list `augments` [{ skill, share, rollKinds }]: its true skill × share (default 1) × its tier is added to the effective skill of every roll or check that asks for the augmented skill, or only rolls of the listed roll kinds (RollKind) when some are listed. The augmenting skill's tree must be open. Shrewd Dealing augments Barter at share 1 on every roll. **Augment kinds** (D-276, Ali 14/11/2026, AK1 to AK4; src/ruleset/gear.ts augmentK, the one equation): an augment entry (SkillDef.augments or PerkDef.augments) may set `kind`. *plain* (the default) is the rule above. *trade*: the receiving skill gains the giving skill's true skill × share (default AUGMENT\_TRADE\_SHARE 0.5, placeholder) × its tier, and every roll of the giving skill loses the same amount (tradesOut), always while the perk or trait is owned; points are moved, never made, true skill is untouched. *percent*: the receiving skill gains the giving true skill ÷ 100 × share (the rate, default AUGMENT\_PERCENT\_RATE 0.2, placeholder) × its tier × the receiving skill's own true skill (both at 50 add 5, at 100 add 20, at 150 add 45); two percentage augments on one skill stack, the largest in full and the next at STACK\_RATIO, and plain or trade augments never halve them. Every kind learns as below, with its factor in place of share × tier. **First trade:** Fists Do the Talking (PK131), the trait of the Tavern Brawler essence (a placeholder until D-229): Strike trades into Intimidation. The essence pop-up and Essences section name a held or offered essence's trait and quirk beside its points. The percentage kind is for the 120 perks (D-258). **How augmenting skills learn** (Ali, 10/11/2026, AU1–AU5, option B): the roll gets one learning window from its sums, built like any skill's window: the low end is the rolled skill's raw plus each augment's raw × share × tier, minus MARK\_WINDOW; the high end is the rolled skill's max(raw, true) plus each augment's max(raw, true) × share × tier, plus MARK\_WINDOW. Every augment that added to the roll is marked when the opposition is inside that window; the opposition is a check's difficulty, or the other side's true skill plus what its own augments added (AU2). A tie (tier gap 0) marks every skill and augment that went into the roll (AU4). An augment not yet on the sheet counts as raw 0 and learns once its tree opens (AU3). An augment limited to roll kinds learns only from rolls of those kinds (AU5). The rolled skill keeps its own window and opposition (markAugments in src/ruleset/improve.ts). **Sword-dancer** (Ali, 09/11/2026; tier 2 from 16/11/2026): a class that unlocks at Dodge 80 and Light or Medium Weapons 60; its level 1 perk First Steps of the Dance (PK156) opens the Sword-dancer tree (Blade Dance). It mirrors the Swordsman: its skills and perks are meant to be the Swordsman's, so the two are designed together. It has no tree, floors or Start yet. **Starter kit** (Ali, 09/11/2026; pairs rule 10/11/2026): items tagged 'starter'. **Rule for every gear class, including new ones: the starter kit holds one item needing 25 (Common) and one needing 50 (Fine) in that class, and nothing above 50.** Improvised weapons are exempt. Today: light melee dagger / short sword; medium melee hand axe / arming sword, spear; heavy melee woodsman's axe / greatsword; light ranged shortbow / recurve bow; medium ranged flatbow / longbow; heavy ranged light crossbow / stirrup crossbow; light armor gambeson / boiled leather (plus Crude rough clothes); medium armor brigandine / mail hauberk; heavy armor lamellar coat / half plate; shield round shield / kite shield (tests/cases/s143 checks it). After creation the player gets, per gear class, only the highest-level starter item whose equip requirement the build meets (`starterKit`): the weapon whose required skill is highest is held (then the higher level), a met shield goes in the other hand unless the weapon takes two hands, the highest-level armor met is worn, and the rest is carried. The recommended swordsman gets the arming sword, round shield and gambeson, and carries the spear. Crude rough clothes (need 0, stop nothing, no Dodge cost) are in the starter kit too, so the late bloomer starts in them with no weapon (Ali, 09/11/2026). Crude weapons (cudgel, rusty knife) are library items outside the starter kit. **Equipment balance lever** (Ali, 09/11/2026): a standard-kit piece's bonus is EQUIP\_FACTOR × its need (EQUIP\_FACTOR 0.4 for now; it replaces the flat KIT\_BONUS 25), so all equipment is rebalanced with one number: Crude 0, Common +10, Fine +20, Superior +30, Masterwork +40. Kit pieces still share one bonus per roll, the best of them. A minted item of quality 3 or 4 is a level up (EQ11), so its bonus rises one step too. **Quality lever** (QE1): a minted weapon's hit bonus is QUALITY\_HIT\_FACTOR (0.04) × its need × its quality (1–4), and quality 3–4 still moves it a level up (EQ11), so a fine sword gives +2/+4/+9/+12 hit. Damage boosts and armor and tool quality keep their tables for now (QE2 open). **Rule of thumb for all gear:** an item's stats scale with its need. Armor will get its own lever and shields a lever for their pool (QE3, under discussion). The recommended build (`recommendedBuild`, one source for the screen and tests), for every Start: Medium Weapons 40, Parry 25, Dodge 10, Endurance 15, Eyesight 5, Earshot 5; tags Medium Weapons, Parry, Endurance. It holds the Common hand axe and wears crude clothes; no Fine (50) starter piece can be met at creation now.

**Random identity** (Ali, 14/11/2026): the creation screen opens on a random name, gender, age and personality, all editable, and its Random button picks them again without touching the skill points (src/library/spawn.ts randomIdentity). Gender: Man, Woman or Other at even odds. Name: from a placeholder list per gender (src/library/names.ts; Other draws from both). Age: whole years from the race's youngest age (Youth start; no children, D-316) to just before its Old start (13 to 59 for a human), so no one starts in old-age decline \[Proposed\]; a Start's own age default (StartDef.age) is no longer the opening value. Personality: a random archetype's targets and values on a random Nerve line. Race: a random playable race (below), and the age is rolled in that race's range.

**Race choice** (CC7 a, Ali 14/11/2026): the creation screen's Race picker lists the playable races (RaceDef.playable): Human and Elf. Slime and Dragon were playable for a while (CC8 b) and were taken off again (Ali, 14/11/2026); they stay NPC races, and the body rules below stay ready for any race made playable later. The build stores it (CreationBuild.raceId, left out = Human); the race sets the body type, the innate perks and quirks and the age range (newPlayer, createPlayer), and validateBuild refuses a race that is not playable. **A start a race can't begin** (CC8): when the start's class floors need a skill the race's body can't learn (a Slime has no hands for Medium Weapons or Parry), the start is greyed out for that race and validateBuild refuses it (raceStartBlock); the screen opens on the first start the race can begin. The recommended build for such a race moves the closed skills' points to its open skills, then to other open skills, up to the creation cap, and tags the highest open skills (recommendedBuild(start, race)). **Starter gear by body** (CC8): the starter weapon and shield go in the body's own grip parts (a Human's right arm then left; a Dragon's jaws, one grip, so no shield; a Slime has none, so nothing is held), and only a humanoid body wears the starter armor \[Proposed\]; the rest is carried. Picking another race rolls an age in its range and builds the screen again, since trees and ages can differ, so the skill points go back to the recommended build (src/library/spawn.ts playableRaces).

**Gods and blessings** (DX1, Ali 14/11/2026, "Essences: bested foes, extraction, balance"; the blessing system beyond this is parked as D-311). Gods are a library table (`gods`, IDs GD…, src/library/godIds.ts), each with a narrow field and a standing (`GodDef.rank`, an ordered scale GOD\_RANKS, weakest first; today only `minor`, "Minor god"); beings above them govern wider concepts (to be built up). Every current god is a **minor god** (Ali, 14/11/2026): grand to the average person, but the minimum for the divine, and the Divine NPC rank's anchor (400) matches it. The standing is game-side only: mortals call every god a god, so in-world text (looks, stories, narration) never says "minor". From Beyond up, NPCs skip the player's skill cap (D-314 c, a placeholder), so a Divine NPC plays at 400. Varo (GD1), minor god of extreme fortunes, no blessings yet. Imbra (GD2), minor goddess of essence manipulation (named by Ali, 14/11/2026). A blessing is a perk with `PerkDef.blessing` = its god and its tier, an ordered scale BLESSING\_TIERS that counts up (CC1 b, Ali 14/11/2026): Tier I is the weakest, the blessed start's Tier V is mid-ladder, and higher gods' blessings go on to Tier VI, VII and up with no end (rows are generated to BLESSING\_TIER\_ROWS, 30, in src/scales.ts; raising it adds tiers). Tiers read as numerals only (CC2 a); names may come later. Lore around the gods belongs to the lore thread.

**NPC generation.** All generation runs in code. A template (a preset; NPC Generation NG1–NG21, Questions hub page npc-generation-rework) gives a body type and race, an optional class, a role, a theme, a rank, a minimum for each skill, a personality, a loadout and a control setting. Kinds of NPC:

- **Rolled** (a bandit): each NPC made from it rolls its own person once at spawn, then its values are saved and frozen. Called "unique" until HF15 (Ali, 13/11/2026).
- **Copy** (a wolf, a slime): saves only the template id and live state, and follows the latest template.
- **Unique** (HF15): one specific character, a whole saved sheet (NpcTemplate.unique, a UniqueSheet) spawned exactly as saved at full health, under its own name, pronouns, personality and age (the Weaver gives only its label, band and place). At most once per world (HF11): the Weaver's catalog lists only uniques not yet in the world (catalogs.uniques, with name, classes, level, power and the hidden past; player.power to set it against), and validation refuses a unique already in the world or cast twice (unique_in_world). Uniques live in the code library, in their own file (src/library/uniques.ts, HF34 a); items made in a hero's own story travel in its sheet (itemDefs) and join the library items. **Echoes** (HF18–HF24, HF29, D-243): a Hall of fame hero comes back as an echo (origin 'echo', src/library/echo.ts echoSheet): its sheet at death, achievements, scars, title and essences kept, its age at death. It never learns (no marks). Its gear is soulbound copies of what it had (weapons, shields, armor, accessories and tools, pools full); its coin and other goods stay behind (HF24 c). A soulbound item (ItemInstance.soulbound) is usable only by its owner (boundTo): it can't be picked up, looted, sold, given, dropped, stashed or knocked from a destroyed hand, it is not a Threadbound item's one of a kind (HF19: the hero's original is freed), and it fades when its owner dies. A Threadbound copy keeps only the abilities the hero had unlocked (its own achievements). A beaten echo always offers an essence (no appearance roll); its quality roll goes ECHO_ESSENCE_TIERS (2) tiers up, past Legendary too, and below Success still gives ECHO_ESSENCE_FLOOR (Common). The Weaver (catalogs.uniques past, rule 10) and the Narrator (actors[].echo, rule 32) get who an echo was and how it fell as a hidden note (HF2).

A template may carry a loadout: a list of library item ids given to every NPC made from it (Part 5 §8) \[Proposed\].

**Named presets for the rosters** (TP7–TP20): the people and beasts the roster hooks and groups cast (NR17–NR20, NR27), so the World builder and the library catalog can name them: hunter, healer and village headman (Village folk), knight (Lord's household, Knight Trainee class), bandit and bandit chief (Road bandits), watch sergeant (Town watch), pedlar (Trader class) and hired guard (Travellers), and wolf, wild boar, bear, dog and dire wolf (Wild beasts; the dire wolf carries the Dire prefix). **Layered generation** (NG1–NG9, NG20, NG21; src/library/spawn.ts presetSkills, templateSkills). Every number is a placeholder lever in CONFIG.
- **Rank** (NG3): an ordered scale RANKS (rank\_0 Untrained, rank\_1 Novice, rank\_2 Trained, rank\_3 Veteran, rank\_4 Elite, rank\_5 Paragon, rank\_6 Beyond, rank\_7 Mythic, rank\_transcendent Transcendent, rank\_8 Divine). Keys are stable and order is the row position (`rankPos`): Transcendent (D-335, placeholder) was added between Mythic and Divine on its own key, so saved keys keep their meaning. Each row of RANK\_ROWS gives a skill anchor and a level: 15/L1, 30/L2, 50/L8, 65/L12, 75/L15, 100/L20 (NR44: set by Ali after a simulated fighter played typical scenarios from a 100-point creation build at level 0, with health, morale and stamina kept through each scenario; it reached Paragon at about L20), and past Paragon two levels for every 5 skill points, twice the Elite-to-Paragon rate, because raw training stops at 100 and those skills come only from essences, gear and perks (NR44, Ali: the earlier past-Paragon levels were too low; NR45 asks to confirm): 150/L40, 200/L60, 300/L100 (Transcendent, placeholder), 400/L140 (Divine raised from 300 to 400 by Ali, 14/11/2026: minor gods are the minimum for the divine). Per-rank tables (RANK\_ROWS, RANK\_TRAITS) are keyed by rank key. Past the last row each step adds RANK\_BEYOND\_STEP (anchor +100, level +40) and the name gains a + (Divine+, Divine++); such keys count on from Divine's number (rank\_9 is Divine+). **Level from skills** (NR39 a): an NPC's level is the rank table read backwards on the average of its own High-band (tagged) skills (`levelAtSkill`, `levelFromSkills`): between two anchors the level moves evenly, below Untrained it falls toward 0, past Divine it goes on by RANK\_BEYOND\_STEP; at least 1. At spawn it reads the rolled skills (spread included); a live NPC's (`actorLevel`) reads its true skills, so essences and growth count. An NPC with a class takes its class level; an echo or other unique keeps its own level. **Grandeur** (NR40 a; scale GRANDEUR mundane, ordinary, grand): every role and theme has one (`grandeur`), and an NPC takes the higher of the two; a seat of the Great (its roster entry) and a unique are always grand. The level from skills is multiplied by CONFIG.GRANDEUR\_LEVEL\_MULT (mundane ×0.75, ordinary ×1, grand ×1.25, placeholders). Mundane: Worker, Hunter, Healer, and the Village folk, Town folk and Travellers themes; grand: Knight; the rest ordinary. A theme may rename ranks (ThemeDef.rankNames).
- **Role** (NG1, NG2; library table npcRoles, IDs RO…): which skills the NPC is built around, in three bands.
