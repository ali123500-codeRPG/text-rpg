## Bug log

The play page's Bugs page (Ali, 11/11/2026): Report bug files the player's note as code player_report with the story, turn and last six lines, then sends every new report and open bug to Claude at once (BG-27): a comment sent to Claude that wakes the build thread, which triages each bug to the thread that owns it. The list shows new reports (marked New), newest first, then open bugs, newest number first; the Kind column names the code in words ("Agent fallback", "Your report") with the raw code in its tip. Send open bugs to Claude sends them again.

Every bug found or reported, in any thread or in play, gets a fixed number (BG-n). Every agent takes one past the highest number in this table and its archive (`bug-log-archive.md`) on the latest `main`, in the PR that adds the row, so a clash shows as a merge conflict and a number is never shared or reused (Ali, 20/11/2026, RH24 a on the Questions hub page "Repo home set-up": the old counter, `bugs_meta/counter` in the play page's db, is retired, because agents that cannot reach that db could not use it). The game never takes one (BF45, Ali, 14/11/2026): it files each report unnumbered, and Claude numbers it at triage. Each real bug gets one number, and repeats of the same bug share it (the bug row lists the reports it came from in `reports`); each report row then gets status numbered and `as` (its BG-n), or not\_a\_bug. A thread that finds a bug takes the next number itself, the same way. Each real bug from an in-game report also gets a GitHub issue, so any desk can claim the fix (RH24 a). Always mention a bug by its BG-n.

The game files a report at `bugs/new-<time>` (status new) for every bug code it logs: any `invalid_` code, and view\_leak, invalid\_target, unlisted\_reveal, planner\_late, agent\_fallback, call\_failed, refused, invalid\_json, weaver\_off\_catalog, weaver\_fallback, weaver\_timeout, routine\_fallback, routine\_skip, reward\_repaired, quest\_goal\_gap and turn\_check (src/save/bugs.ts BUG\_CODES). Plain game outcomes, such as a blocked move or a refused sale, are not bugs. A build thread that reviews a filed bug adds it to this table, sets its db status (open, fixed or wont\_fix), and names the claim issue of the work that fixes it ("#n": the issue exists before the first commit, so no second commit is needed; a test fails on "this PR"). From BG-327 a row is one line on what was wrong (at most 160 characters); the story is in `docs/bug-fix-log.md` (WF3 a). Rows up to BG-326 keep the form of their day.
