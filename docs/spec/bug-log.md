## Bug log

The play page's Bugs page (Ali, 11/11/2026): Report bug files the player's note as code player_report with the story, turn and last six lines, then sends every new report and open bug to Claude at once (BG-27): a comment sent to Claude that wakes the build thread, which triages each bug to the thread that owns it. The list shows new reports (marked New), newest first, then open bugs, newest number first; the Kind column names the code in words ("Agent fallback", "Your report") with the raw code in its tip. Send open bugs to Claude sends them again.

Every bug found or reported, in any thread or in play, gets a fixed number (BG-n): the number of its claim issue, labelled `bug`, so issue #1480 is BG-1480 (`docs/instructions.md` section 2; the owner, 21/11/2026, #1472). GitHub Issues are the bug register: an open issue is an open bug, a closed one is fixed, won't fix or a duplicate. Its story is its own `docs/bugs/BG-n.md`. Numbers below 1000 are the old count, taken one past the highest in this table and its archive (`bug-log-archive.md`): their rows stay here and in the archive, and no new row is added (the old counter, `bugs_meta/counter` in the play page's db, is retired too, RH24 a). The game never takes one (BF45, Ali, 14/11/2026): it files each report unnumbered, and Claude numbers it at triage by opening its issue. Each real bug gets one number, and repeats of the same bug share it (the bug row lists the reports it came from in `reports`); each report row then gets status numbered and `as` (its BG-n), or not\_a\_bug. A thread that finds a bug opens its issue the same way. Always mention a bug by its BG-n.

The game files a report at `bugs/new-<time>` (status new) for every bug code it logs: any `invalid_` code, and view\_leak, invalid\_target, unlisted\_reveal, planner\_late, agent\_fallback, call\_failed, refused, invalid\_json, weaver\_off\_catalog, weaver\_fallback, weaver\_timeout, routine\_fallback, routine\_skip, reward\_repaired, quest\_goal\_gap and turn\_check (src/save/bugs.ts BUG\_CODES). Plain game outcomes, such as a blocked move or a refused sale, are not bugs. A build thread that reviews a filed bug opens its issue and sets its db status (open, fixed or wont\_fix).
